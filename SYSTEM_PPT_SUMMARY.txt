Video Enhancement Studio
System Summary for Stage Presentation
=====================================

1. System Positioning
---------------------
This project is a video-assisted understanding enhancement system.

It has two nested layers:

1) Outer video enhancement system
- Input: raw video
- Output: an interactive HTML player with subtitles, enhancement overlays, gallery, and global panels
- Goal: improve comprehension while the user watches the video

2) Inner SVG dynamic graphic generation system
- Input: selected enhancement topic + layout context + scene context + visual direction
- Output: SVG animation / diagram assets
- Goal: transform abstract transcript content into visual explanatory graphics

In short:
the system does not simply add subtitles or pictures, but builds a pipeline from transcript understanding -> enhancement decision -> context-aware content generation -> synchronized HTML presentation.

4. Detailed Phase Explanation
-----------------------------

Phase 1: Whisper transcription
- Extracts sentence-level transcript with timestamps
- Produces the temporal text foundation for the whole system

Phase 2: Semantic segmentation
- Groups sentence-level transcript into semantic segments
- Uses embedding similarity to merge semantically coherent chunks
- This avoids generating enhancement content sentence by sentence

Phase 3: decision and semantic routing
- Uses LLM to decide whether a segment deserves enhancement
- Basic output classes:
  - svg
  - text
  - none
- Extended output classes:
  - misconception
  - mechanism_chain
- Also constructs a global_summary of the whole video

Phase 4: layout analysis
- Finds safe overlay regions on video frames
- Uses full-screen search instead of fixed corner placement
- Avoids faces / salient areas / crowded regions
- Outputs overlay position, size, safety score, and local region context

Phase 5: scene analysis
- Extracts visual style from the actual video frames
- Computes color hierarchy, complexity, continuity, saturation, etc.
- Produces scene-aware design guidance for downstream SVG/text generation

Pre-Phase 6: HTML skeleton
- Builds the base interactive HTML player first
- Allows later content to be appended incrementally
- This supports early visual feedback instead of waiting for all SVG generation to finish

Phase 6: content generation
- Generates:
  - SVG animation
  - text cards
  - misconception content
  - mechanism chains
- Appends each generated result into HTML incrementally

Phase 7: finalization
- Completes output organization
- Produces final enhanced HTML player


5. Core Context Injection Design
--------------------------------
One of the most important characteristics of this system is that generation is not done from isolated transcript text.
It explicitly injects multiple levels of context.

5.1 Global summary context
- Produced in decision_agent.py
- Summarizes the whole video:
  - main topic
  - key concepts
  - content structure
  - visual opportunities
  - domain
- Used as a global semantic prior for later judgment and generation

Why it matters:
- Prevents local segments from being interpreted out of context
- Makes enhancement generation more globally coherent

5.2 Sliding local context window
- decision_agent.py uses previous and following segments as local context
- Helps the system understand what the current segment means in discourse flow

Why it matters:
- Improves classification robustness
- Helps distinguish isolated remarks from truly meaningful explanation segments

5.3 Layout context
- Produced in layout_agent.py
- Includes:
  - overlay width / height
  - x / y placement
  - position tag
  - safety score
  - region_context

Why it matters:
- Content generation is aware of available spatial budget
- SVG and text are not generated as if they were always full-screen
- Supports layout-aware adaptation

5.4 Scene context
- Produced in scene_agent.py
- Includes:
  - color hierarchy
  - background / accent / text colors
  - visual complexity
  - scene continuity
  - design_guide

Why it matters:
- Makes generated overlays visually compatible with the underlying video
- Avoids hard visual clashes between enhancement content and source footage

5.5 SVG shared visual context
- Implemented through:
  - svg_agent/shared_context.py
  - svg_agent/state.py
- Stores:
  - main concept
  - sub concepts
  - relationships
  - visual elements
  - color scheme
  - layout structure
  - animations
  - design decisions

Why it matters:
- SVG generation is not a single prompt call
- It is a coordinated multi-step design process with persistent shared state

The inner SVG system is itself a structured multi-agent generation workflow.

7. Existing Enhancement Modalities
----------------------------------

7.1 SVG animation
- Best for abstract concepts, processes, architectures, comparisons, and explanatory diagrams

7.2 Text card
- Best for concise conceptual reinforcement, reframing, or takeaway emphasis

7.3 Misconception correction
- Detects segments likely to cause misunderstanding
- Converts them into correction-oriented enhancement content

7.4 Mechanism chain
- Detects process-like or causal segments
- Converts them into stage-based explanation chains

7.5 Global concept graph
- Persistent global panel
- Represents the knowledge structure of the full video
- Synchronizes with time as the video progresses


8. Innovation Points
--------------------
The current system already contains several meaningful innovation points for both product and research presentation.

8.1 Multi-layer context-aware generation
This is not plain transcript-to-overlay generation.
It combines:
- transcript semantics
- global summary
- local context window
- layout context
- scene context
- shared SVG design context

This is a strong systems-level contribution.

8.2 Incremental HTML generation
- HTML skeleton is created before all content is complete
- Phase 6 appends generated content progressively
- This supports real-time feedback during long generation runs

This is useful both for product iteration and system usability.

8.3 Video-aware placement instead of static placement
- layout_agent searches the whole frame
- avoids faces and salient regions
- chooses safer negative space for overlays

This makes the system more like an adaptive video augmentation engine than a static overlay tool.

8.4 Scene-aware visual styling
- scene_agent extracts actual visual properties from the video
- downstream generation adapts style and color accordingly

This improves coherence between enhancement content and source footage.

8.5 Nested multi-agent SVG generation
- The SVG subsystem is internally structured as an agent workflow with state and shared context
- It includes validation and review loops

This gives the SVG path a strong "designed generation" characteristic.

8.6 Expansion beyond plain text / image insertion
The new modules push the system from:
- local text
- local SVG

toward:
- misconception-aware explanation
- mechanism-oriented explanation
- global knowledge structure


9. New Research-Oriented Extensions
-----------------------------------

9.1 Confusion / misconception module
File:
- confusion_agent.py

Function:
- Finds segments where viewers may form a subtly wrong mental model
- Produces:
  - confusion_risk
  - likely_misconception
  - correct_understanding
  - why_confusing

Research value:
- Moves beyond summarization into misconception-aware explanation

9.2 Mechanism chain module
File:
- mechanism_agent.py

Function:
- Finds process / transformation / causal-chain segments
- Produces:
  - chain_title
  - stages
  - links
  - current_focus_stage
  - visual_hint

Research value:
- Moves beyond static illustration into explicit mechanism scaffolding

9.3 Concept graph module
File:
- concept_graph_agent.py

Function:
- Uses LLM-guided extraction to produce:
  - nodes
  - edges
  - timeline_updates
  - clusters

Research value:
- Introduces global knowledge structure instead of only local overlay content


10. Data / Cache Organization
-----------------------------
The system is designed for repeated experimentation on the same video.

Typical cached artifacts include:
- whisper_transcript.txt
- semantic_segments.txt
- enhancement_decisions.txt
- global_summary.txt
- layout_positions.txt
- scene_analysis.txt
- confusion_analysis.json
- mechanism_chains.json
- concept_graph.json
- concept_graph_extractions.json
- temp_analysis/assets/svg/*.svg

Why this matters:
- expensive stages are reusable
- later front-end or Phase 6 iterations do not always require re-running earlier analysis
