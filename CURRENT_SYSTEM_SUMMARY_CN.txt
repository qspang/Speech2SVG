视频辅助理解增强系统：当前工作总结（中文）
==================================================

一、系统定位
------------

本系统是一个“视频辅助理解增强系统（Video Understanding Enhancement System）”。
它的目标不是简单给视频叠加字幕或插图，而是根据视频语义内容、场景信息与布局信息，
自动生成适合当前片段的增强内容，并以 HTML 播放页的形式与视频同步展示。

当前系统由两层组成：

1. 外层：视频增强系统
   负责视频转录、语义分段、增强决策、布局计算、场景分析、内容生成、HTML 播放页构建。

2. 内层：SVG 动态生成系统（以 svg_simple 为主）
   负责将适合可视化表达的语义片段转化为 SVG / Animated SVG 叠加内容。

当前阶段的核心思想是：

- 外层系统决定“什么时候增强、用什么增强、放在哪里、和视频如何融合”
- 内层系统决定“SVG 具体画什么、怎么动、如何与语义和画面上下文匹配”


二、整体处理流程
----------------

当前已经实际落地并能运行的主流程如下：

1. Phase 1：Whisper 转录
2. Phase 2：语义分段
3. Phase 3：增强决策（svg / text / none，并附带动画倾向）
4. Phase 4：布局计算（避让人脸、寻找负空间）
5. Phase 5：场景分析与风格提取
6. Pre-Phase 6：HTML 骨架生成
7. Phase 6：内容生成与增量 append
8. Phase 7：最终整理与输出 HTML


三、主流程图（文字版）
----------------------

输入视频文件
  -> Phase 1: Whisper 转录
  -> 输出 whisper_transcript.txt
  -> Phase 2: 语义分段
  -> 输出 semantic_segments.txt
  -> DecisionAgent（Phase 3 增强决策）
     -> 输出 enhancement_decisions
     -> 主分类: svg / text / none
     -> 附加: svg_mode_hint / motion_worthiness / motion_grammar_hint / animation_reason
     -> 内部使用 global_summary
     -> 内部使用 local context window（prev-3 / next-3）

DecisionAgent 之后有两条辅助支路：

  A. decisions + global_summary
     -> mechanism_agent
     -> 更新后的 decisions（svg / text / mechanism）

  B. segments + decisions + global_summary
     -> ConceptGraphAgent
     -> 输出 concept_graph

更新后的 decisions
  -> LayoutProcessor / LayoutAgent（Phase 4 布局计算）
  -> 输出 layout_positions
  -> 输出 layout_context / region_context

enhancement_points + layout_context
  -> SceneAgent（Phase 5 场景分析）
  -> 输出 scene_analysis
  -> 输出 scene_context / design_guide

concept_graph
  -> HTMLGenerator（Pre-Phase 6）
  -> 先生成 HTML 骨架（视频 / 字幕 / 画廊 / 概念图区域）

enhancement_points + layout_context + scene_context
  -> ContentAgent（Phase 6 内容生成）

ContentAgent 分成两条内容生成路径：

  路径 1:
  -> TextAgent
  -> 生成 text card / mechanism 文字内容

  路径 2:
  -> svg_simple 子系统
  -> VisualStrategy
  -> SVGGenerator
  -> SVGValidator
  -> 生成 SVG / Animated SVG

TextAgent 与 svg_simple 的输出
  -> HTMLGenerator 增量 append
  -> 生成一个内容点，追加一个到 HTML

最终
  -> Phase 7 输出 enhanced_video.html


Context 交互关系（简化版）
------------------------

1. global_summary
   semantic_segments -> DecisionAgent -> global_summary
   global_summary -> DecisionAgent
   global_summary -> mechanism_agent
   global_summary -> ConceptGraphAgent

2. local context
   semantic_segments -> DecisionAgent
   DecisionAgent 在当前片段分类时使用 prev-3 / next-3 局部窗口

3. layout_context / region_context
   decisions -> LayoutProcessor -> layout_context / region_context
   layout_context / region_context -> svg_simple.VisualStrategy
   layout_context / region_context -> TextAgent / HTML 渲染样式

4. scene_context / design_guide
   enhancement_points -> SceneAgent -> scene_context / design_guide
   scene_context / design_guide -> svg_simple.VisualStrategy
   scene_context / design_guide -> TextAgent
   scene_context / design_guide -> HTMLGenerator


四、外层视频系统的模块说明
------------------------

1. 转录与语义聚合

- Whisper 负责将视频内容转成带时间戳的英文字幕。
- 之后使用句向量模型将连续句子聚合为语义段，而不是机械按固定秒数切片。
- 这样后续增强的最小单位不再是“时间窗口”，而是“语义完整片段”。

作用：
- 减少碎片化增强
- 让每个增强点更接近真实表达单元


2. 决策模块（Decision Agent）

Decision Agent 是当前系统的关键路由器。
它负责判断每个语义段是否值得增强，以及更适合什么类型的增强。

当前保留的主分类是：

- svg
- text
- none

同时，对于被判为 svg 的片段，系统还会附加动画相关提示：

- svg_mode_hint
- motion_worthiness
- motion_grammar_hint
- animation_reason

这些字段不再直接强绑定模板，而是作为后续 SVG 策略生成的参考。

当前 Decision Agent 使用了两类上下文：

- 全局摘要（global summary）
  帮助系统理解整段视频的主题、结构、关键概念和领域。

- 局部滑动窗口上下文（prev-3 / next-3）
  帮助系统理解当前字幕段中的代词、省略和上下文依赖。

这意味着：
系统不是只看一行字幕做判断，而是“在全局主题 + 局部语境”下做增强决策。


3. 布局模块（Layout Agent）

Layout Agent 负责决定增强内容在视频画面中的放置位置。
它不是固定把内容放在左上角或右上角，而是尝试根据视频帧内容寻找安全区域。

当前主要考虑：

- 人脸区域避让
- 画面显著性区域避让
- 不同时间点多帧采样
- 区域局部颜色与复杂度提取

输出包括：

- x / y / width / height
- 安全分数
- 区域上下文 region_context

region_context 会继续传给后面的内容系统，用于决定：

- 背景透明度
- 文本对比色
- 局部图形风格


4. 场景分析模块（Scene Agent）

Scene Agent 负责从视频帧中提取更全局的视觉风格信息。

当前输出重点包括：

- 主色 / 辅色 / 文本色
- 饱和度、亮度、温度
- 视觉复杂度
- 设计指导 design_guide

design_guide 会给后续 SVG 和文本生成提供风格约束。

当前已经从偏“工具风/赛博风”的提示，逐步调整到更适合论文展示与学术 demo 的风格：

- scholarly
- editorial
- instrument-grade
- research demo


5. HTML 生成模块（HTML Generator）

HTML Generator 负责把所有增强内容最终组织成一个可播放的页面。

当前页面结构大致是：

- 左侧：视频播放器与视频浮层
- 右侧：字幕时间线、增强内容画廊、全局概念图
- 下方局部面板：机制链、误解纠正等辅助区域

当前系统支持增量 append：

- Phase 6 每生成一个内容点
- 就立即追加到 HTML 中

这样用户不需要等全部生成完，能够更早看到结果。


五、内层 SVG 系统（svg_simple）的当前设计
-----------------------------------------

当前的 svg_simple 已经从“固定模板拼装”切回到“LLM 直接生成 SVG 代码”为主。

当前链路如下：

        文本片段 + layout_context + scene_context + motion_hint
                                   │
                                   v
                     ┌────────────────────────┐
                     │ VisualStrategy         │
                     │ 生成轻量 design brief   │
                     └──────────┬─────────────┘
                                │
                                v
                     ┌────────────────────────┐
                     │ SVGGenerator           │
                     │ LLM 直接写 SVG 代码     │
                     └──────────┬─────────────┘
                                │
                                v
                     ┌────────────────────────┐
                     │ SVGValidator           │
                     │ 修正不安全动画与结构    │
                     └────────────────────────┘


1. VisualStrategy 的作用

VisualStrategy 现在不再产出一堆模板字段，而是产出一个尽量轻量的设计 brief。

当前 brief 重点字段包括：

- visual_type
- core_topic
- display_title
- display_subtitle
- key_elements
- layout_concept
- style_directive
- animation_intent
- animation_notes
- scene_alignment

这个 brief 的目标不是直接控制模板，而是告诉后面的 LLM：

- 这段内容真正要表达什么
- 应该采用怎样的构图逻辑
- 动画应该是强解释型还是轻量增强型
- 如何与视频场景色彩和氛围对齐


2. SVGGenerator 的作用

SVGGenerator 当前的主路径是：

- 直接调用 LLM
- 根据 design brief 生成完整 SVG / Animated SVG 代码

这意味着：
- 不再优先用 deterministic composer 做“几个框几个词”的拼装
- 尽可能利用当前大模型在 SVG 代码生成上的能力

当前 prompt 特别强调：

- 不要生成随机单词标签
- 不要退化成 generic box-and-arrow filler
- 要尽量使用 meaningful shapes、visual metaphor、spatial composition
- 即使是 static 风格的图，也要带一点轻动画


3. SVGValidator 的作用

SVGValidator 当前主要负责：

- 清理不安全、容易错位的动画写法
- 对 SVG 结构做兜底修正

目标不是压制动画，而是保证：

- SVG 可以正常叠加到视频中
- 不因为动画写法问题跑到错误位置


六、当前支持的增强形式
----------------------

1. 普通文字卡（text card）

适合：
- 定义
- 规则
- 关键术语
- 高密度信息点


2. SVG / Animated SVG

适合：
- 结构关系
- 流程
- 比较
- 层级
- 抽象概念图解

当前策略是：
- 适合强动画表达的片段：做更明显的 animated SVG
- 不适合强动画表达的片段：仍然尽量加入轻量动态元素


3. 机制链（mechanism chain）

这部分是结构化辅助解释模块，不是 SVG 子系统本体。
它更偏向机制过程的流程表达。



4. 全局概念图（global concept graph）

这部分是全局、持续存在的侧边区域。
它不是单个时间点的浮层，而是整段视频的知识结构摘要。


七、当前系统已经落地的关键创新点
--------------------------------

1. 多层上下文注入，而不是单点字幕增强

当前系统不只是根据单句字幕做增强，而是综合使用：

- 全局摘要
- 局部上下文窗口
- 布局上下文
- 区域上下文
- 场景风格上下文

这使得生成内容不再是“脱离视频环境的插图”，
而是“与视频语义和视频画面共同约束下的增强内容”。


2. 外层视频系统 + 内层 SVG 系统的双层架构

当前系统不是单一生成器，而是两层协作：

- 外层系统负责理解视频、做增强决策与视频对齐
- 内层系统负责生成可视化 SVG 内容

这个分层很重要，因为它让“何时增强”和“如何画图”被明确拆开。


3. 决策驱动的解释介质选择

系统当前虽然仍保留 `svg / text / none` 三类主分类，
但决策模块已经不是简单分类器，而更像解释介质路由器：

- 这段是否值得增强
- 更适合文字还是图形
- 如果是图形，动画应该强还是弱

4. 面向视频画面的布局与风格适配

很多类似系统只考虑语义，不考虑视频画面本身。

当前系统已经明确考虑：

- 画面空白区域
- 人脸避让
- 局部区域颜色
- 局部区域复杂度
- 场景整体色彩风格

因此增强内容不是简单叠加，而是对视频画面的自适应融合。


5. SVG 生成从“静态装饰”走向“带动画的解释图”

当前已经明确把 SVG 的目标从：

- 静态插图

推进到：

- 带动画的 explanatory SVG

即使不是强动画图，也尽量加入轻量动态元素。

这使得 SVG 不只是“好看”，而是在视频中承担更强的解释作用。




八、总结
--------------------------------------

可以把当前系统概括为：

“一个上下文感知的视频辅助理解增强系统。
它首先基于全局与局部语义上下文，识别视频中值得增强的片段；
然后综合布局与场景信息决定增强内容的放置与风格；
最后利用 LLM 直接生成与视频语义和画面环境对齐的 SVG / Animated SVG 或文字卡内容，
并以增量式 HTML 播放页的形式与视频同步展示。”

如果更强调 SVG 子系统，可以写成：

“系统中的 SVG 子模块不再依赖固定模板拼装，
而是通过轻量设计 brief + LLM 直接生成 SVG 代码，
从而让图形构图与动画效果更充分地利用大模型的创作能力。”


九、当前阶段可重点展示的贡献
----------------------------

如果做阶段性 PPT 或论文初稿，当前最适合重点展示的贡献有：

1. 提出一个双层视频增强架构
   外层负责视频理解与增强对齐，内层负责 SVG 可视化生成。

2. 提出上下文感知的增强决策方式
   同时利用 global summary 与 local context 做决策。

3. 提出 layout-aware + scene-aware 的增强生成机制
   不是只看语义，而是让视频画面本身参与生成。

4. 将 SVG 生成从静态图解推进到 Animated SVG 增强
   并强调动画不是简单装饰，而是解释能力的一部分。

5. 提供可增量预览的 HTML 视频增强界面
   适合作为研究系统平台与实验原型。
